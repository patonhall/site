## 2. Book Space pipeline — working, verified end to end

Proven on 2026-08-18: form → Sheet → Apps Script → Kit → GitHub Issue →
`approved` label → Action → `events.json` → Calendar. Two real runs, issues
#1 and #2, both approved and written.

Three bugs were found and fixed, each hiding the next:

1. The client submitted the bare space id (`"A"`) instead of the Google
   Form's own option string (`"A - Blackboard"`). The Space / Zone question
   is multiple-choice with no "Other", so Google validated the answer against
   its option list and **rejected the entire response** — no Sheet row, no
   trigger, no issue. Invisible because the page posts with `mode:'no-cors'`,
   which returns an opaque response, so the visitor was always told
   "Request submitted".
2. `KIT_API_KEY` was unset, so `kitUpsertAndTag_` threw on the *first* line
   of `onFormSubmit` and destroyed the request before GitHub was contacted.
3. `GITHUB_TOKEN` was never set at all.

**Do not reintroduce the shape that made these invisible.** All three
scripts now open the GitHub Issue *before* touching Kit, tag via
`tagQuietly_` (logs, never throws), and throw on a non-201 from GitHub
instead of returning an unusable parsed error body.

Each script has a read-only `runSelfTest()` that checks triggers (including
whether the trigger is spreadsheet-sourced — a form-sourced event has no
`namedValues`), script properties, the Kit key and every tag it uses, GitHub
access, and repo readability. **Run it before debugging anything by hand.**

## 3. Hard-won gotchas

- **Google Forms multiple-choice validates against a hand-maintained option
  list.** A value not on it fails the whole submission silently. Never put
  anything that changes (events, courses) in a dropdown — use short answer.
- **Verify `entry.` ids off the live form**, not a prefill URL: fetch
  `.../viewform` and parse `var FB_PUBLIC_LOAD_DATA_`. This is what caught
  bug 1 and confirmed the Event Name field.
- **GitHub Pages serves `max-age=600`.** A "the fix didn't work" report
  minutes after a deploy is usually a cached asset. Hard-refresh first.
- **A no-conflict booking auto-closes its issue.** Use
  `gh issue list --state all`; the default view shows nothing.
- **`github-actions[bot]` pushes to `main`** when the `approved` label is
  added, so `git push` can be rejected mid-session. Rebase, don't force.
- **`assets/data/events.json` is written by `admin_server.save_items`** with
  `ensure_ascii=True`. Hand-edits should round-trip through that function or
  they leave a phantom diff.
- **Never regenerate an event's `uid`.** Attendance and iCalendar both key on
  it; regenerating orphans RSVPs and strands stale calendar entries.
